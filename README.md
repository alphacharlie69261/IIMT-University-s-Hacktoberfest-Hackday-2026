# Hacktoberfest Hackday 2026 — IIMT University 🚀

### Build. Collaborate. Share.

Welcome to the project submission repository for **Hacktoberfest Hackday 2026 at IIMT University!**

This repository brings together the projects created by our participants. Use it to showcase your work, discover what other teams built, and practise contributing through GitHub pull requests.

🔗 **[View the event on MLH](https://events.mlh.com/events/15385-)**

## 📌 What do you need to submit?

Every attendee should:

1. Publish their project on their own GitHub account.
2. Share their project and Hackday experience in a LinkedIn post.
3. Include their GitHub project link and LinkedIn post link in their team’s submission file.

**Submit one pull request per team.** Include all team members and their links in that submission.

> Your project code belongs in your own project repository. This repository collects a Markdown file describing your project and linking to your work.

## 1. Publish your project on GitHub

Make sure your project repository is public and contains:

- Your project’s source code.
- A README explaining the problem, solution, and main features.
- The technologies used.
- Instructions for installing and running the project.
- Screenshots or a demo link, if available.
- Credits for teammates, external resources, and existing code used.

For team projects, maintain a shared project repository. Each member should also have the project on their own GitHub account—for example, through a fork—and clearly credit the team.

Never upload passwords, API keys, access tokens, or private `.env` files.

## 2. Share your project on LinkedIn

Publish a LinkedIn post covering:

- Your participation in **Hacktoberfest Hackday 2026 at IIMT University**.
- Your project’s name and the problem it solves.
- What you built and the technologies you used.
- Your teammates and what you learned.
- Your GitHub project link.
- Screenshots or a demo video, if available.

Suggested hashtags:

`#Hacktoberfest #Hacktoberfest2026 #IIMTUniversity #Hackday #OpenSource`

Copy the link to your actual LinkedIn **post**, not just your profile. Make sure the organizers can view it.

## 3. Create your team’s submission file

All submissions go inside the **`submissions/`** folder.

Create one Markdown file named after your team:

```text
submissions/your-team-name.md
```

Examples:

- `submissions/code-crafters.md`
- `submissions/pixel-pioneers.md`
- `submissions/byte-builders.md`

### File naming rules

- Use lowercase letters.
- Replace spaces with hyphens.
- End the filename with `.md`.
- Choose a unique filename. If your team name is already taken, add a short suffix.
- Edit only your own team’s submission file.

## 4. Open a pull request — beginner guide

You can submit directly through the GitHub website.

### A. Fork this repository

Open this repository and click **Fork**, then **Create fork**.

A fork is your own copy of this submission repository.

### B. Create a submission branch

In your fork, open the branch selector and create a branch named:

```text
submission/your-team-name
```

Make sure this branch is selected before adding your file.

### C. Add your team’s file

Click **Add file → Create new file**.

In the filename field, enter:

```text
submissions/your-team-name.md
```

Paste the submission template and fill in your team’s details.

Use **Preview** to check that headings, links, and the team table display correctly.

### D. Commit your file

Click **Commit changes** and enter a clear commit message:

```text
Add project submission: Your Team Name
```

Save the change to your submission branch.

A commit saves a recorded version of your changes.

### E. Create your pull request

From your fork, select **Contribute → Open pull request**. You may also see a **Compare & pull request** button.

Check that:

- **Base repository:** the organizers’ original submission repository.
- **Base branch:** the original repository’s default branch.
- **Head repository:** your fork.
- **Compare branch:** `submission/your-team-name`.

Review the **Files changed** tab. Your PR should contain only your team’s submission file.

Use this PR title:

```text
Project Submission: Your Team Name — Your Project Name
```

Copy and complete this PR description:

```markdown
## Submission details

- Team name:
- Project name:
- Submission file: submissions/your-team-name.md
- Main project repository:

## Checklist

- [ ] We have submitted one Markdown file for our team.
- [ ] Every team member is listed with their contribution.
- [ ] Every attendee has included a project link on their own GitHub account.
- [ ] Every attendee has included their LinkedIn post link.
- [ ] Our project repositories are public and accessible.
- [ ] Our project README explains the project and how to run it.
- [ ] All links have been checked.
- [ ] Existing code and external resources are credited.
- [ ] No secrets or private credentials are included.
- [ ] This PR changes only our team's submission file.
```

Click **Create pull request** to send your submission for review. Submit it as a ready-for-review PR, rather than leaving it as a draft.

🎉 **Your project has now been submitted for review!**

## 5. Respond to review feedback

Organizers may request missing details or corrections.

To update your submission:

1. Open your fork.
2. Select the same submission branch.
3. Edit your team’s file.
4. Commit the changes.

Changes committed to that branch will appear in your existing pull request. You do not need to create another PR.

Once the organizers approve and merge your PR, your submission will appear in this repository.

## ✅ Submission guidelines

- Submit one file and one PR per team.
- Provide accurate information about your project and contributions.
- Clearly distinguish work completed during the Hackday from pre-existing work.
- Credit all external code, tools, datasets, and assets.
- Do not modify another team’s submission or unrelated repository files.
- Keep discussions and review comments respectful.
- A live deployment is optional; include clear run instructions when no live demo is available.

> **Hacktoberfest participation:** This PR records your Hackday project submission. Its acceptance does not guarantee that it qualifies toward official Hacktoberfest contribution requirements.
